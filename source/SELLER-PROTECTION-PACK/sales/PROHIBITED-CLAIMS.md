# Claims to avoid / approved wording

Never claim “100% ready”, “bug-free”, “100% secure”, “production-ready”, “fully GDPR/CCPA compliant”, “supports every country”, “online payments integrated”, “courier integrated” or “all tests pass” unless the exact claim is independently evidenced and still accurate.

Preferred wording:
- “ShopEasy 2.8.94 is a configurable development template; it does not promise production readiness, legal compliance or support for every market.”
- “The UI has English, Sorani Kurdish, Arabic and Dutch (Belgium) language packs; translation completeness and native wording must be verified page by page.”
- “Cash on delivery is the current default payment method. Mollie card checkout requires eligible merchant setup, credentials and live approval; other named providers are contact/onboarding references.”
- “Country-specific shipping, tax, legal notices, privacy workflows, and production security controls require additional configuration and validation.”
- “273 automated tests passed in the previous reported run; 4 dependency-backed suites were blocked by package installation failure. Re-run all tests after a clean dependency install before release.”
- “Thirty-day email support is offered only if included in the signed order; specify start date, hours, response target and scope.”

Requested buyer editing/rebranding scope is an intent record only; existing grants remain UNKNOWN. See `../BUYER-USE-INTENT.md` and the root rights-clearance register.
